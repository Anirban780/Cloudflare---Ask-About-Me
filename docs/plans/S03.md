## 1. Approach

1. **Create `src/config.ts`**:

     - `CHUNK_OVERLAP_CHARS: 120`
     - `CHUNK_MIN_CHARS: 40`

     - `MAX_CHUNKS_PER_DOC: 100`
     - `TOP_K: 8`, `MAX_RESULTS: 5`, `MAX_PER_DOC: 2`, `MIN_SCORE: 0.5`
     - `MAX_CONTEXT_CHARS: 6000`, `MAX_HISTORY_MESSAGES: 20`
     - `MAX_INPUT_CHARS: 1000`, `MAX_OUTPUT_TOKENS: 600`
     - `MAX_TOOL_STEPS: 4`, `RATE_LIMIT_PER_HOUR: 30`

2. **Implement `src/rag/chunker.ts`**:
   - Pure function without side effects or I/O:
     `export function chunkMarkdown(doc: { docId: string; title: string; content: string }, opts?: Partial<ChunkerOptions>): Chunk[]`
   - Data types:
     `export type Chunk = { id: string; index: number; section: string; text: string; embedText: string };`
   - Algorithm (SPECS §6.3):
     1. Normalize line endings (`\r\n` -> `\n`), collapse 3+ blank lines to 2, trim content.
     2. Identify markdown headings (`#` to `###`) to create a hierarchical section path (e.g. `"Experience > Acme Corp"`). Pre-heading content assigned to `"Overview"`.
     3. Split section text into paragraphs on blank lines (`\n\n+`). Preserve list items together unless exceeding `CHUNK_MAX_CHARS`.
     4. Greedily pack paragraphs up to `CHUNK_MAX_CHARS`.
     5. For oversize paragraphs exceeding limit, split cleanly on sentence boundaries (`[.!?]\s+`), and if still too large, on whitespace word boundaries. Never split mid-word.
     6. Apply intra-section overlap: each subsequent chunk in the same section starts with the last `CHUNK_OVERLAP_CHARS` (word-boundary aligned) of the preceding chunk. Never overlap across different sections.
     7. Drop chunks shorter than `CHUNK_MIN_CHARS`.
     8. Set deterministic IDs: `${docId}:${index}` (0-indexed across entire document).
     9. Format embedText: `${title} — ${section}\n${text}`.
     10. If chunk count > `MAX_CHUNKS_PER_DOC`, throw descriptive error.

3. **Install `vitest`**:
   - Allowlisted dev dependency per SKILLS.md R7.
   - Add `"test": "vitest run"` in `package.json`.

4. **Implement `test/chunker.test.ts`**:
   - Write tests for each of the 9 properties required by SPECS.md §6.3:
     1. Determinism: Same input yields identical chunks and IDs.
     2. Chunk length bounds: None exceeds `CHUNK_MAX_CHARS`; none is below `CHUNK_MIN_CHARS`.
     3. Sentence completeness: Every non-trivial sentence appears in at least one chunk.
     4. Section path nesting: Correct paths for `#`, `##`, `###`.
     5. Section isolation: Overlap never crosses section boundaries.
     6. Heading-less docs: Documents without headings chunk with `"Overview"` section.
     7. Word integrity: Single very long paragraphs split without breaking words.
     8. Whitespace / empty: Empty or whitespace-only inputs return `[]`.
     9. Max chunk cap: Documents resulting in > `MAX_CHUNKS_PER_DOC` throw an error.

## 3. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Sentence splitter breaking abbreviations or decimals | Use regex that requires punctuation followed by whitespace and uppercase/start. Fall back gracefully. |
| Overlap duplication causing infinite loops | Overlap is strictly bounded to `CHUNK_OVERLAP_CHARS` and sliced from the end of the previous chunk text. |
| Incompatible test framework | Use standard `vitest` which integrates seamlessly with Vite and TypeScript. |
