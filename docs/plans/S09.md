> **Slice:** S9

> **Companions:** `docs/SPECS.md` §8.3, §9, §10, §13 (F-11, F-12, F-15, F-16), §15.

## 1. Approach

1. **`getGitHubProjects` Tool (`src/agent/tools.ts`, F-11)**:
   - Tool description guiding Llama 3.3 to fetch public GitHub repositories and open-source contributions.
   - Input schema: `topic?: string (≤60)` via Zod.
   - Remote fetch: `https://api.github.com/users/${GITHUB_USER}/repos?sort=pushed&per_page=30`.
   - Headers: `User-Agent: ask-about-me`, `Accept: application/vnd.github+json`.
   - Cloudflare cache options: `cf: { cacheTtl: 3600, cacheEverything: true }`.
   - Filters out forked repositories (`!repo.fork`).
   - If `topic` is provided, filters case-insensitively on `name`, `description`, or `topics`.
   - Limits output to top 8 active repositories.
   - Graceful degradation: handles GitHub 403 / 429 rate limit or network outages with a friendly fallback message and direct profile link.

2. **`leaveMessageForOwner` Tool (`src/agent/tools.ts`, F-12)**:
   - Tool description allowing visitors to leave contact messages, interview invitations, or questions for Anirban.
   - Input schema: `senderName: string (≤80)`, `senderEmail: string (email)`, `message: string (≤1000)`.
   - Marked with `needsApproval: true` to enforce Human-In-The-Loop client approval before message persistence.
   - Persists message record into SQLite `owner_inbox` table.
   - Returns `{ delivered: true, message: "Thank you! Your message has been saved for Anirban." }`.

3. **`owner_inbox` Storage Architecture (`src/agent/portfolio-agent.ts`)**:
   - Create SQLite table in `PortfolioAgent.onStart()`:
     ```sql
     CREATE TABLE IF NOT EXISTS owner_inbox (
       id INTEGER PRIMARY KEY AUTOINCREMENT,
       created_at TEXT NOT NULL DEFAULT (datetime('now')),
       sender_name TEXT NOT NULL,
       sender_email TEXT NOT NULL,
       message TEXT NOT NULL,
       visitor_id TEXT,
       status TEXT NOT NULL DEFAULT 'new'
     );
     ```
   - Export `@callable() saveInboxMessage(...)` and `@callable() getInboxMessages()` methods on `PortfolioAgent` to allow cross-DO access via a dedicated DO singleton (`owner-inbox`), plus D1 table support if `env.DB` is present.

4. **Admin HTTP API Endpoints (`src/server.ts`, §9, F-12, F-16)**:
   - `GET /api/admin/inbox`:
     - Bearer token authentication against `env.ADMIN_TOKEN`.
     - Queries `owner_inbox` from the storage layer (DO singleton or D1) and returns `{ messages: [...] }`.
   - `POST /api/admin/ask`:
     - Bearer token authentication against `env.ADMIN_TOKEN`.
     - Non-streaming answer generator for evaluation harnesses using the identical system prompt and tools.
     - Returns `{ query: string, answer: string, toolCalls: string[] }`.

5. **Client Approval Card UI (`src/app.tsx`, §10, F-12, F-15)**:
   - Specializes `ToolPartView` for `leaveMessageForOwner` when `part.state === "approval-requested"`.
   - Renders clear sender details, email, and message preview with primary "Approve & Send" and secondary "Reject" buttons.
   - Updates tool activity indicators ("Checking GitHub...", "Sending message to Anirban...").

6. **Unit Tests (`test/github.test.ts`, `test/inbox.test.ts`)**:
   - Test GitHub tool: repo filtering, topic matching, fork removal, 403 fallback handling.
   - Test Inbox tool: message insertion, validation, storage schema compliance.

## 3. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| GitHub API rate limiting in unauthenticated requests | Cache responses with Cloudflare cache (`cf: { cacheTtl: 3600 }`) and return a friendly direct link to GitHub profile when a 403 or 429 occurs. |
| Tool approval bypass | Tool uses AI SDK native `needsApproval: true`; the server only executes after client emits an approved confirmation chunk. |
| Multi-tenant inbox isolation | Messages are centralized in the durable `owner-inbox` Durable Object instance (and D1 if bound), ensuring `GET /api/admin/inbox` sees all submitted messages regardless of visitor session. |
